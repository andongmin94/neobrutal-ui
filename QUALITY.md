## Template and chart evolution

The product introduction and README no longer lead with the derivative-project background. LICENSE, Credits & license, and the README attribution notice remain intact.

The four installed templates now include an editorial archive with combined topic/search filters and sorting; a CMS content editor with a plain-text reading preview, local save and discard; expanded portfolio case studies; and categorized profile links with explicit clipboard feedback. CMS state remains local to the current page and is not a publishing backend.

The chart landing view now presents three original analytical examples: revenue against a target, signup-stage conversion, and response-time percentiles against a budget. Each uses one dataset for the plot, calculated summary, and expandable data table. The 47 underlying chart examples remain as reference patterns; they have not all been redesigned. The chart primitive no longer overwrites the color, width, and opacity of every SVG path.

The chart source index is generated by the existing docs generate command and ignored by Git rather than storing a second copy of every example. The generator and all source examples remain versioned.

The product-evolution browser suite covers the new state transitions, calculated values, escaped preview content, chart line styling, and narrow-screen accessibility. Its presence is not proof of a passing run. Use the exact commit's Verify results. Gallery thumbnail assets still depict the earlier template layouts and need to be refreshed after visual review.

## Installable analytical recipes

Revenue, conversion, and latency charts are independently installable as chart-revenue-target, chart-signup-conversion, and chart-service-latency. Their authoritative files live in registry/src/components/ui. The former docs-only copies are removed; documentation previews and the chart gallery import the generated mirrors. The source dialog displays the exact installed source, including its default export.

Each recipe declares Recharts and the Chart/Card registry dependencies. It uses the normal UI alias resolution rather than a hard-coded target, and it does not reinstall the design-system base. The existing base setup is still required. Each recipe has a dedicated usage, installation, source-configuration, and accessibility document linked directly from its gallery card.

The existing Verify workflow installs each chart independently in both Next.js and Vite in addition to the aggregate consumer checks. Chart contracts compare source, generated mirror, gallery code, and built JSON. Browser checks follow each gallery installation link, operate its documentation preview, and inspect its installation endpoint. These checks do not replace a rendered consumer-app audit or custom-alias testing.

## Remaining product gates

1. Exercise the exact README init/add path, individual installs beyond the three analytical charts, custom aliases, existing files, and theme retention after later installations. Build success alone is not a CSS or browser-runtime check of a consuming application.
2. Review every public variant and state at mobile/desktop widths and in all supported themes, including keyboard/touch, long Korean/English/Japanese content and IME, disabled/error/loading states, nested overlays, scrolling, and reduced motion.
3. Review optional FormDescription/FormMessage composition, absent IDREF targets, user-supplied IDs/descriptions, ref/event composition, and cross-field error recovery beyond the covered fixtures.
4. Verify templates in consuming projects without docs CSS. Gallery previews are not substitutes for installed-template checks.
5. Audit all documentation/API examples and search timing/error states. Review screenshots for clipped shadows, doubled borders, alignment, wrapping, and state contrast. Automated axe checks are not a comprehensive visual or assistive-technology audit.

A gate is complete only when its check was actually performed and the result recorded. No percentage score or absence of an obvious error substitutes for a verified gate.
