Use Navigation Menu for navigation between pages. Put direct destinations in NavigationMenuLink and grouped destinations inside a trigger/content pair. Use [Menubar](/docs/menubar) for application commands.

## Usage

```tsx
import {
  NavigationMenu,
  NavigationMenuList,
  NavigationMenuItem,
  NavigationMenuLink,
  navigationMenuTriggerStyle,
} from "@/components/ui/navigation-menu";

export default function SiteNavigation() {
  return (
    <NavigationMenu aria-label="Main navigation">
      <NavigationMenuList>
        <NavigationMenuItem>
          <NavigationMenuLink href="/docs" className={navigationMenuTriggerStyle()}>
            Documentation
          </NavigationMenuLink>
        </NavigationMenuItem>
        <NavigationMenuItem>
          <NavigationMenuLink href="/templates" className={navigationMenuTriggerStyle()}>
            Templates
          </NavigationMenuLink>
        </NavigationMenuItem>
      </NavigationMenuList>
    </NavigationMenu>
  );
}
```

## API reference

| Prop / part | Purpose | Default |
| --- | --- | --- |
| `NavigationMenu.value` / `onValueChange` | Controlled expanded item | Uncontrolled |
| `NavigationMenu.defaultValue` | Initially expanded item | `null` |
| `NavigationMenu.delay` / `closeDelay` | Hover open and close delay | Base UI defaults |
| `NavigationMenu.orientation` | Trigger keyboard navigation | `horizontal` |
| `NavigationMenuItem.value` | Stable grouped-item identifier when controlling state | Optional |
| `NavigationMenuLink.href` / `render` | Native destination or router-link composition | Anchor |
| `NavigationMenuLink.active` | Current destination styling and semantics | `false` |

## Accessibility

Use real links and meaningful text. A trigger opens content rather than navigating. Preserve link props and refs when composing a router link. Mark the current destination and test keyboard and touch interactions. Provide a compact mobile layout rather than squeezing a wide desktop menu.
