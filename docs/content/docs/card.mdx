Use Card to group related information and actions. It supplies visual structure, not navigation, selection, or heading semantics. Put real buttons and links inside it rather than making a generic container clickable.

## Usage

```tsx
import { Card, CardContent, CardDescription, CardHeader, CardTitle } from "@/components/ui/card";

export default function ProjectCard() {
  return (
    <Card className="w-full max-w-sm">
      <CardHeader>
        <CardTitle>
          <h2>Design system</h2>
        </CardTitle>
        <CardDescription>Shared components for the product team.</CardDescription>
      </CardHeader>
      <CardContent>
        <p>12 components are ready for review.</p>
      </CardContent>
    </Card>
  );
}
```

## API reference

| Prop / part | Purpose | Default |
| --- | --- | --- |
| `Card` | Root surface and shadow | `div` |
| `CardHeader` | Title, description, and optional action layout | `div` |
| `CardTitle` / `CardDescription` | Text styling; not heading elements | `div` |
| `CardAction` | Action beside header content | `div` |
| `CardContent` / `CardFooter` | Main content and action region | `div` |
| `className` | Width and layout on each part | — |

## Accessibility

Put a real heading inside CardTitle when the card starts a section, using the level appropriate to the page. Name icon-only actions. Avoid nested interactive elements when adding a card-wide link. A collection of cards may use a list outside the component.
