Use Pagination when a collection has addressable pages. It styles links but does not fetch data, calculate page counts, or manage the current page. For client-side table state, see [Data Table](/docs/data-table).

## Usage

```tsx
import {
  Pagination,
  PaginationContent,
  PaginationItem,
  PaginationLink,
  PaginationNext,
} from "@/components/ui/pagination";

export default function ArticlePages() {
  return (
    <Pagination aria-label="Article pages">
      <PaginationContent>
        <PaginationItem>
          <PaginationLink href="?page=1" isActive>
            1
          </PaginationLink>
        </PaginationItem>
        <PaginationItem>
          <PaginationLink href="?page=2">2</PaginationLink>
        </PaginationItem>
        <PaginationItem>
          <PaginationNext href="?page=2" />
        </PaginationItem>
      </PaginationContent>
    </Pagination>
  );
}
```

## API reference

| Prop / part | Purpose | Default |
| --- | --- | --- |
| `Pagination` | Named navigation landmark | Labelled pagination |
| `PaginationLink.href` | Destination URL | Unset |
| `PaginationLink.isActive` | Current-page state and aria-current | `false` |
| `PaginationLink.size` | Button-style size | `icon` |
| `PaginationPrevious.text` / `PaginationNext.text` | Directional label | `Previous` / `Next` |
| `PaginationEllipsis` | Omitted pages | Non-interactive |

## Accessibility

Provide actual destinations and mark exactly one current page. Anchors have no native disabled state: omit unavailable Previous/Next links or render non-interactive text instead of keeping a clickable link styled as disabled. Use a specific collection label when a page has multiple pagination controls.
