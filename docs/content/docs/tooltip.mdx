Use Tooltip for brief extra context, not essential instructions or interactive content. Keep TooltipProvider around the relevant controls. A tooltip is not a substitute for its trigger's accessible name.

## Usage

```tsx
import { Info } from "lucide-react";
import { Button } from "@/components/ui/button";
import { TooltipProvider, Tooltip, TooltipTrigger, TooltipContent } from "@/components/ui/tooltip";

export default function InformationHint() {
  return (
    <TooltipProvider>
      <Tooltip>
        <TooltipTrigger
          render={<Button size="icon" variant="outline" aria-label="Workspace information" />}
        >
          <Info aria-hidden="true" />
        </TooltipTrigger>
        <TooltipContent>Visible to workspace members only.</TooltipContent>
      </Tooltip>
    </TooltipProvider>
  );
}
```

## API reference

| Prop / part | Purpose | Default |
| --- | --- | --- |
| `TooltipProvider.delay` | Opening delay in milliseconds | `0` through this wrapper |
| `Tooltip.open` / `onOpenChange` | Controlled visibility | Uncontrolled |
| `Tooltip.defaultOpen` | Initial visibility | `false` |
| `TooltipTrigger.render` | Focusable-control composition | Primitive trigger |
| `TooltipContent.side` / `align` | Preferred placement | `top` / `center` |
| `TooltipContent.sideOffset` | Trigger gap | `4` |

## Accessibility

Give icon-only controls their own aria-label and hide decorative icons. Keep tooltip text concise. Do not put buttons, links, or required form help inside a tooltip. Touch users may not encounter it, so controls must remain understandable without hover content.
