Use Tabs to switch between closely related views without navigating to a new page. Match trigger values to TabsContent values. Use links for independently navigable destinations.

## Usage

```tsx
import { Tabs, TabsList, TabsTrigger, TabsContent } from "@/components/ui/tabs";

export default function ProjectTabs() {
  return (
    <Tabs defaultValue="overview" className="w-full max-w-md">
      <TabsList aria-label="Project views">
        <TabsTrigger value="overview">Overview</TabsTrigger>
        <TabsTrigger value="activity">Activity</TabsTrigger>
      </TabsList>
      <TabsContent value="overview">Project summary and current goals.</TabsContent>
      <TabsContent value="activity">No recent activity.</TabsContent>
    </Tabs>
  );
}
```

## API reference

| Prop / part | Purpose | Default |
| --- | --- | --- |
| `Tabs.value` / `onValueChange` | Controlled active panel | Uncontrolled |
| `Tabs.defaultValue` | Initial panel; specify a matching trigger value | Base UI default |
| `Tabs.orientation` | Horizontal or vertical navigation | `horizontal` |
| `TabsList.activateOnFocus` | Activate with arrow-key focus; false requires Enter or Space | `true` |
| `TabsList.loopFocus` | Wrap focus at the ends | `true` |
| `TabsList.variant` | default or line styling | `default` |
| `TabsTrigger.value` / `TabsContent.value` | Matching panel identifier | Required |
| `TabsTrigger.disabled` | Unavailable tab | `false` |
| `TabsContent.keepMounted` | Retain an inactive panel in the DOM | `false` |

Tabs delegates selection, keyboard navigation, refs, and rendering to Base UI. Use its `render` prop for element composition and `activateOnFocus` for manual activation; no second state or keyboard implementation is maintained.

## Accessibility

Name the tab list. Keep labels short and test arrows, Home/End, and Tab into the panel. Set `activateOnFocus={false}` on TabsList when opening a panel triggers expensive work. Do not hide critical instructions behind an undiscoverable tab.
