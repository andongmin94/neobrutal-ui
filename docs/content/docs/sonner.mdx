Install one Toaster near the application root and call toast from sonner when something happens. This wrapper styles notifications; it does not send requests, persist messages, or confirm that an operation succeeded.

## Installation

Complete the [base setup](/docs/installation). For manual installation:

<Installation component="sonner">

```bash
npm install sonner@^2.0.7 next-themes@^0.4.6
```

Create **`components/ui/sonner.tsx`**:

<include cwd lang="tsx">
  ./src/components/ui/sonner.tsx
</include>
</Installation>

The example also uses Button. In a real application move Toaster to your root layout. Docs previews already have a site-level host.

## Usage

```tsx
"use client";
import { toast } from "sonner";
import { Button } from "@/components/ui/button";
import { Toaster } from "@/components/ui/sonner";

export default function NotificationExample() {
  return (
    <>
      <Button onClick={() => toast("This is a local preview notification.")}>
        Show notification
      </Button>
      <Toaster closeButton />
    </>
  );
}
```

## API reference

| Prop / part | Purpose | Default |
| --- | --- | --- |
| `Toaster.theme` | light, dark, or system | Theme provider value or system |
| `Toaster.position` | Stack placement | Sonner default |
| `Toaster.closeButton` | Visible dismissal control | Sonner default |
| `Toaster.toastOptions` | Shared duration and appearance | Theme styles provided |
| `toast` / `toast.success` / `toast.error` | Enqueue a message | Imported from sonner |

## Accessibility

Keep messages concise and avoid repeated announcements. Important errors also belong beside the failed task so they remain available after a toast disappears. Show success only after the operation succeeds. Mount only one Toaster in the application.
