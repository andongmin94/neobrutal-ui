This is an installable recipe with sample payment data, not a generic table component accepting arbitrary data and columns. Copy it, define your row type and columns, then connect application data. Use [Table](/docs/table) for a simple semantic table without state management.

The row menu copies the payment ID and reports success or failure beside that row. If clipboard access is unavailable, the message displays the ID for manual copying. Customer navigation and payment-detail screens are application responsibilities, not inactive menu entries in this recipe.

## Usage

```tsx
import DataTable from "@/components/ui/data-table";

export default function PaymentsExample() {
  return <DataTable />;
}
```

The default export initially renders the bundled example. Replace its `data` and `columns` definitions in the installed file; do not pass unsupported `data` or `columns` props to this export.

## API reference

| Recipe part | Purpose | Initial behavior |
| --- | --- | --- |
| `DataTable` | Default exported component without generic props | Sample payments |
| `data` / `columns` | Row model and column definitions in source | Payment schema |
| `sorting` / `columnFilters` | Client sorting and filtering | Empty state |
| `rowSelection` / `columnVisibility` | Selected and hidden rows/columns | Empty state |
| `useReactTable` | Row models and state callbacks | Configured locally |
| `getPaginationRowModel` | Client pagination | TanStack default page size |

## Accessibility

Preserve semantic table elements, meaningful column headers, and names on row-selection controls. Sorting exposes its direction with `aria-sort`. Row actions announce their result without depending on a toast provider. Keep empty, loading, and error states distinct. The sample uses payment IDs as stable row IDs; configure your own stable IDs and server state for large or server-paginated datasets. This sample is not a database grid or backend integration.
