Use Scroll Area when a panel needs its own scrollable content. Constrain the height for vertical scrolling or the width for horizontal scrolling. The wrapper creates both scrollbar orientations and a corner automatically; Base UI shows each bar when its axis overflows. Do not replace ordinary page scrolling without a clear layout need.

## Usage

```tsx
import { ScrollArea } from "@/components/ui/scroll-area";

export default function ActivityList() {
  return (
    <ScrollArea
      className="h-48 w-full max-w-sm rounded-base border-2 border-border"
      aria-label="Recent activity"
    >
      <ul className="space-y-3 p-4">
        {Array.from({ length: 12 }, (_, index) => (
          <li key={index}>Workspace update {index + 1}</li>
        ))}
      </ul>
    </ScrollArea>
  );
}
```

## API reference

| Prop / part | Purpose | Default |
| --- | --- | --- |
| `ScrollArea.className` | Root bounds and layout | Unbounded unless styled |
| `ScrollArea.aria-label` / `aria-labelledby` | Name the focusable scrolling region | Unset |
| `ScrollArea.overflowEdgeThreshold` | Threshold for native overflow-edge state | `0` |
| `ScrollBar.orientation` | Vertical or horizontal scrollbar for direct Base UI compositions | `vertical` |
| `ScrollBar.keepMounted` | Keep a scrollbar mounted without overflow | `false` |
| Children | Content inside the viewport | Required for useful scrolling |

## Accessibility

An `aria-label` or `aria-labelledby` names the viewport and exposes it as a region. Base UI manages its keyboard focusability when content overflows.

Ensure keyboard users can reach and scroll the region. Name substantial regions and do not trap wheel or touch scrolling unnecessarily. Both scrollbars appear while hovering, scrolling, or focusing the region. Do not add `ScrollBar` inside `ScrollArea` children: the wrapper already owns the bars. The separately exported `ScrollBar` is available when composing Base UI's Root, Viewport, Content, and Corner directly.
