Use Menubar for application commands such as File and View, not as the default navigation of a marketing site. Each MenubarMenu owns a trigger and content. Use [Navigation Menu](/docs/navigation-menu) for page navigation.

## Usage

```tsx
"use client";
import { useState } from "react";
import {
  Menubar,
  MenubarMenu,
  MenubarTrigger,
  MenubarContent,
  MenubarItem,
} from "@/components/ui/menubar";

export default function FileMenu() {
  const [message, setMessage] = useState("No command selected.");
  return (
    <div className="grid gap-3">
      <Menubar>
        <MenubarMenu value="file">
          <MenubarTrigger>File</MenubarTrigger>
          <MenubarContent>
            <MenubarItem onClick={() => setMessage("Created a local draft.")}>
              New draft
            </MenubarItem>
            <MenubarItem disabled>Export</MenubarItem>
          </MenubarContent>
        </MenubarMenu>
      </Menubar>
      <p role="status">{message}</p>
    </div>
  );
}
```

## API reference

| Prop / part | Purpose | Default |
| --- | --- | --- |
| `Menubar.value` / `onValueChange` | Controlled open-menu identifier | Uncontrolled |
| `Menubar.defaultValue` | Initial open menu | Empty string |
| `Menubar.loop` | Wrap trigger keyboard navigation | `true` |
| `MenubarMenu.value` | Stable identifier | Generated if omitted |
| `MenubarContent.align` / `sideOffset` | Popup placement | `start` / `8` |
| `MenubarCheckboxItem.checked` / `onCheckedChange` | Checked command state | Uncontrolled |

## Accessibility

Keep labels short and commands meaningful. Arrow keys navigate triggers and menu items; Escape dismisses. MenubarShortcut only displays text: implement and test the corresponding keyboard handler separately. Make disabled commands visually identifiable, and do not use application-menu semantics for an ordinary list of website links.
